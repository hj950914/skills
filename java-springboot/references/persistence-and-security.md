# 持久化、事务与安全规范

## 目录

- 事务
- 数据访问通则
- MyBatis 与 MyBatis-Plus
- Spring Data JPA
- 安全

## 事务

- 将事务边界优先放在应用服务或明确的业务入口。
- 不在 Controller、Mapper 或 Repository 层随意开启事务。
- 让事务范围尽可能小。
- 查询场景可按项目约定使用 `@Transactional(readOnly = true)`。
- 避免在数据库事务中执行耗时远程调用、文件操作或长时间等待。
- 注意 `@Transactional` 对 private 方法和同类自调用不生效。
- 捕获异常时不得意外阻止事务回滚。
- 需要分布式一致性时遵循项目已有的消息、补偿或事务方案，不自行设计简化版方案。

## 数据访问通则

- 先识别项目使用 MyBatis、MyBatis-Plus、JPA 还是其他方案，不擅自替换持久化框架。
- 让 Mapper 或 Repository 负责数据访问，不承载业务规则。
- 避免 N+1 查询、加载无关字段和不受控的批量操作。
- 对更新和删除明确约束条件，防止无条件修改数据。
- 使用项目已有分页方案，不在内存中伪分页。

## MyBatis 与 MyBatis-Plus

- 对用户输入使用 `#{}` 参数绑定，禁止直接拼接到 `${}`。
- 仅在表名、列名或排序字段等必要场景使用 `${}`，并先经过白名单校验。
- 避免在循环中逐条查询，优先批量查询。
- 保持复杂 SQL 可读；必要时使用 XML 和明确的 `resultMap`。
- 为更新和删除语句提供明确条件。
- 进行批量操作时考虑数据库参数数量和事务范围。
- 只查询实际需要的字段，避免无意义的 `SELECT *`。

## Spring Data JPA

- 不直接向 API 暴露 Entity。
- 防止懒加载异常、N+1 查询和不受控级联。
- 对复杂查询使用明确的 JPQL、原生 SQL、Specification 或投影。
- 根据查询场景选择 DTO 投影，避免加载无关字段。

## 安全

- 遵循项目现有的 Spring Security、网关或 IAM 认证授权方案。
- 使用 BCrypt、Argon2 等成熟算法哈希密码，不自行实现加密算法。
- 对 SQL 使用参数绑定，对动态字段使用白名单。
- 输出到 HTML 等上下文时正确编码，防止 XSS。
- 在服务端执行资源访问权限校验，不只依赖前端隐藏按钮。
- 对上传、下载和路径参数防范目录穿越。
- 不让日志和错误响应泄露敏感信息。
- 不在代码中写入真实密钥，即使只是测试或示例。
